# Engineering portfolio

Four case studies from systems I built, written the way I would explain them to a colleague: the problem, the decisions with their reasons, what I measured, and what is not done. Numbers are dated and come from the project's own files.

| Case study | One line | Code |
|---|---|---|
| [RankWant](case-studies/01-rankwant.md) | A competitive-programming platform whose judge runs untrusted code; sandbox chosen by a measured bake-off | [public](https://github.com/menarzullayev/rankwant) |
| [Project Alpha](case-studies/02-project-alpha.md) | A ten-stage documentation pipeline where a claim without evidence cannot pass | [public](https://github.com/menarzullayev/project-alpha) |
| [tg-solver](case-studies/03-tg-solver.md) | An agent that may reply only after independent checks, and the measurement of its verifier | measurement is [public](https://github.com/menarzullayev/agent-verification-study); the tool is private |
| [Attendance system](case-studies/04-attendance-system.md) | Face recognition for a state medical university; the design is mostly what I removed | private (client work) |

## How to read these

- Each page ends with **What is not done**. I put it there on purpose.
- A decision names the alternative I rejected and the reason.
- When I was wrong, the page says so and how I found out.

## Diagrams

The four diagrams are generated by [`build_diagrams.py`](build_diagrams.py) (standard library only) in light and dark variants, so the page follows your GitHub theme.

```bash
python build_diagrams.py
```

See [NOTICE](NOTICE.md) for what is deliberately left out.
